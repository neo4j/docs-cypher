= Chronological comparison operators
:description: Information about Cypher's chronological comparison operators.
:table-caption!:
:page-role: new-neo4j-2026.11 cypher-25-only

Chronological comparison operators compare temporal values either by xref:values-and-types/temporal.adoc#cypher-temporal-instants[instant] or by representation.
Cypher contains the following chronological comparison operators:

* Ordering:
** `IS [NOT] BEFORE`
** `IS [NOT] AFTER`
* Equality:
** `IS [NOT] SAME INSTANT`
** `IS [NOT] SAME REPRESENTATION`

[[chronological-comparison-syntax]]
== Syntax

[source, syntax]
----
expr IS [NOT] BEFORE expr
expr IS [NOT] AFTER expr
expr IS [NOT] SAME INSTANT expr
expr IS [NOT] SAME REPRESENTATION expr
----

.Operator results
[options="header"]
|===
| Operator | Result

| `IS [NOT] BEFORE`
| `true` if the instant of the left operand is earlier than the instant of the right operand.

| `IS [NOT] AFTER`
| `true` if the instant of the left operand is later than the instant of the right operand.

| `IS [NOT] SAME INSTANT`
| `true` if both operands denote the same instant.

| `IS [NOT] SAME REPRESENTATION`
| `true` if both operands have the same representation.

|===

`NOT` negates the comparison using ternary logic.
`true` becomes `false`, `false` becomes `true`, and `null` remains `null`.

[[instant-and-representation]]
== Instant and representation

The instant of a value is the point in time it denotes, regardless of the zone or offset used to write it.
The representation of a value is its type together with its component values, including its time zone or offset where the type has one.
For a `DATETIME` value, the representation is the local date-time together with the time zone or offset.
For a `TIME` value, the representation is the local time together with the offset.

The operators `IS BEFORE`, `IS AFTER`, and `IS SAME INSTANT` compare instants.
The operator `IS SAME REPRESENTATION` compares representations, in the same way as `=`.
Consequently, two zoned values can denote the same instant and still have different representations.

.Compare zoned values by instant and by representation
// tag::expressions_predicates_chronological_comparison_operators_instant_representation[]
[source, cypher]
----
RETURN datetime('2020-01-01T12:00Z') IS SAME INSTANT datetime('2020-01-01T13:00+01:00') AS sameInstant,
       datetime('2020-01-01T12:00Z') IS SAME REPRESENTATION datetime('2020-01-01T13:00+01:00') AS sameRepresentation
----
// end::expressions_predicates_chronological_comparison_operators_instant_representation[]

.Result
[role="queryresult",options="header,footer",cols="2*<m"]
|===
| sameInstant | sameRepresentation

| true | false

2+d|Rows: 1
|===

Non-zoned values, such as `DATE` and `LOCAL DATETIME`, have no time zone or offset, so their instant and their representation coincide.
Instant comparison and representation comparison therefore reduce to value comparison.

[[operand-rules]]
== Operand rules

Both operands must be temporal values of the same type group for a non-null result.
The type groups are `DATE`, `LOCAL TIME`, `TIME`, `LOCAL DATETIME`, and `DATETIME`.

* If either operand is `null`, every chronological comparison operator returns `null`.
* Non-temporal operands, including `DURATION` values, are not comparable.
* Temporal operands of different type groups do not compare, for example `DATE` with `DATETIME`, or `LOCAL TIME` with `TIME`.

For operands that do not compare, the positive ordering operators `IS BEFORE` and `IS AFTER` return `null`, while the positive equality operators `IS SAME INSTANT` and `IS SAME REPRESENTATION` return `false`.

.Compare incompatible operands
// tag::expressions_predicates_chronological_comparison_operators_incompatible_operands[]
[source, cypher]
----
RETURN date('2020-01-01') IS BEFORE datetime('2020-01-01T00:00Z') AS beforeMixedGroups,
       date('2020-01-01') IS SAME INSTANT datetime('2020-01-01T00:00Z') AS sameInstantMixedGroups,
       1 IS NOT BEFORE 2 AS notBeforeNumbers,
       1 IS NOT SAME INSTANT 2 AS notSameInstantNumbers
----
// end::expressions_predicates_chronological_comparison_operators_incompatible_operands[]

.Result
[role="queryresult",options="header,footer",cols="4*<m"]
|===
| beforeMixedGroups | sameInstantMixedGroups | notBeforeNumbers | notSameInstantNumbers

| null | false | null | true

4+d|Rows: 1
|===

[[operator-precedence]]
== Precedence

.Operator precedence
[NOTE]
====
Operator precedence defines how Cypher groups expressions when parentheses are not present.
The following order is relevant (higher precedence first):

* Arithmetic operators: `+`, `-`, `*`, `/`, `%`, `^`
* Chronological comparison operators, and other predicate operators such as `IN`, `STARTS WITH`, `ENDS WITH`, `CONTAINS`, `=~`, and `IS NULL`
* Comparison operators: `=`, `<>`, `<`, `\<=`, `>`, `>=`
* `NOT`
* `AND`
* `XOR`
* `OR`

This means that `a IS BEFORE b + c` compares `a` with `b + c`, and that `a IS BEFORE b = c` compares the result of `a IS BEFORE b` with `c`.
When in doubt, add parentheses to make the intended grouping explicit.
====

A second chronological comparison requires parentheses.
For example, `a IS BEFORE b IS BEFORE c` is not a valid chain, but the following expression is:

// tag::expressions_predicates_chronological_comparison_operators_precedence[]
[source, cypher]
----
RETURN (datetime('2026-10-05T09:00:00Z') IS BEFORE datetime('2026-10-05T12:00:00+02:00'))
       AND (datetime('2026-10-05T12:00:00+02:00') IS BEFORE datetime('2026-10-05T11:00:00Z')) AS chained
----
// end::expressions_predicates_chronological_comparison_operators_precedence[]

.Result
[role="queryresult",options="header,footer",cols="1*<m"]
|===
| chained

| true

1+d|Rows: 1
|===

== Examples

.`IS BEFORE` in a `WHERE` subclause
// tag::expressions_predicates_chronological_comparison_operators_where[]
[source, cypher]
----
MATCH (e:Event)
WHERE e.at IS BEFORE datetime('2026-10-05T11:00:00Z')
RETURN e.name AS name, e.at AS at
ORDER BY name
----
// end::expressions_predicates_chronological_comparison_operators_where[]

.Result
[role="queryresult",options="header,footer",cols="2*<m"]
|===
| name | at

| "Planning" | 2026-10-05T12:00+02:00

2+d|Rows: 1
|===

.`CASE` expression
// tag::expressions_predicates_chronological_comparison_operators_case[]
[source, cypher]
----
MATCH (e:Event)
RETURN e.name AS name,
       CASE e.at
         WHEN IS BEFORE datetime('2026-10-05T11:00:00Z') THEN 'before'
         WHEN IS SAME INSTANT datetime('2026-10-05T11:00:00Z') THEN 'same instant'
         ELSE 'after'
       END AS position
ORDER BY name
----
// end::expressions_predicates_chronological_comparison_operators_case[]

.Result
[role="queryresult",options="header,footer",cols="2*<m"]
|===
| name | position

| "Planning" | "before"
| "Retrospective" | "after"
| "Review" | "same instant"

2+d|Rows: 3
|===

[NOTE]
====
A range index on the compared property can be used to answer chronological comparison operators.
`IS SAME REPRESENTATION` uses an exact key lookup, in the same way as `=`.
The results are identical whether or not an index exists.
For more information, see xref:indexes/performance-indexes/using-indexes.adoc[The impact of indexes on query performance].
====

.Non-zoned temporal values
// tag::expressions_predicates_chronological_comparison_operators_non_zoned[]

RETURN date('2026-10-05') IS BEFORE date('2026-10-06') AS dateBefore,
       localtime('09:00') IS AFTER localtime('10:00') AS timeAfter,
       localdatetime('2026-10-05T12:00:00') IS SAME INSTANT localdatetime('2026-10-05T12:00:00') AS sameInstant
----
// end::expressions_predicates_chronological_comparison_operators_non_zoned[]
