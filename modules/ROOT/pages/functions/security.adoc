[[query-functions-security]]
= Security functions
:description: Security functions are used to evaluate user attributes when defining attribute-based access control (ABAC) auth rules.
:test-skip: true
:page-role: cypher-25-only
:table-caption!:

Security functions are used to evaluate user attributes in the condition of an link:{neo4j-docs-base-uri}/operations-manual/current/authentication-authorization/attribute-based-access-control/[attribute-based access control (ABAC)] auth rule.

[IMPORTANT]
====
The functions on this page cannot be called directly in queries.
They can only be used in the condition of a `CREATE AUTH RULE` or `ALTER AUTH RULE` command.
For more information about defining auth rules and more extensive examples, see link:{neo4j-docs-base-uri}/operations-manual/current/authentication-authorization/attribute-based-access-control/[Operations Manual -> Attribute-based access control].
====

[role=label--new-Neo4j-2026.06 label--cypher-25-only]
[[functions-security-native-user-tags]]
== abac.native.user_tags()

.Details
|===
| *Syntax* 3+| `abac.native.user_tags()`
| *Description* 3+| Returns the list of tags for the native user.
| *Returns* 3+| `LIST<STRING>`
|===

.Considerations
|===
| `abac.native.user_tags()` cannot be called directly in queries. It can only be used in the condition of a `CREATE AUTH RULE` or `ALTER AUTH RULE` command.
| The function returns an empty list if the user has no tags.
| When evaluating the function in link:{neo4j-docs-base-uri}/operations-manual/current/authentication-authorization/attribute-based-access-control/#linking-external-users-to-native[conjunction with external authentication], the function will return an empty list if the native user is not found (unless link:{neo4j-docs-base-uri}/operations-manual/current/configuration/configuration-settings/#config_dbms.security.require_local_user[`dbms.security.require_local_user`] is set to `true`, in which case the absence of a native user will prevent the user from authenticating).
|===

.+abac.native.user_tags()+
======

The following auth rule grants its role when the native user has the `admin` tag.

.Query
// tag::functions_security_abac.native.user_tags[]
[source, cypher]
----
CREATE AUTH RULE nativeAdminRule
SET CONDITION 'admin' IN abac.native.user_tags()
----
// end::functions_security_abac.native.user_tags[]

======

[[functions-security-oidc-user-attribute]]
== abac.oidc.user_attribute()

.Details
|===
| *Syntax* 3+| `abac.oidc.user_attribute(claimKey)`
| *Description* 3+| Returns the value of the specified user attribute from the OIDC claims. Returns `null` if the attribute is not present.
.2+| *Arguments* | *Name* | *Type* | *Description*
| `claimKey` | `STRING` | The key of the OIDC claim whose value is returned.
| *Returns* 3+| `ANY`
|===

.Considerations
|===
| `abac.oidc.user_attribute()` cannot be called directly in queries. It can only be used in the condition of a `CREATE AUTH RULE` or `ALTER AUTH RULE` command.
| The returned value can be an arbitrarily nested map object that represents the value of the user's `claimKey` claim.
| `null` is returned if the specified attribute is not present in the user's OIDC claims.
|===

.+abac.oidc.user_attribute()+
======

The following auth rule grants its role when the `department` claim in the user's OIDC token is equal to `sales`.

.Query
// tag::functions_security_abac.oidc.user_attribute[]
[source, cypher]
----
CREATE AUTH RULE salesRule
SET CONDITION abac.oidc.user_attribute('department') = 'sales'
----
// end::functions_security_abac.oidc.user_attribute[]

======
