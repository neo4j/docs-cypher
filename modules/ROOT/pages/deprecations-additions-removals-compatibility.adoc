[[cypher-deprecations-additions-removals-compatibility]]
= Additions, deprecations, removals, and compatibility
:description: all of the features that have been removed, deprecated, added, or extended in different Cypher versions.
:test-skip: true  // all deprecations would fail.

// Order of subsections:
//  1. Removals
//  2. Deprecations
//  3. Restrictions
//  4. Updates
//  5. New

Cypher is a language that is constantly evolving.
New features are added to the language continuously, and occasionally, some features become deprecated and are subsequently removed.
All changes to Cypher are introduced in Neo4j versions.

This section lists all of the features that have been removed, deprecated, added, or extended in different versions of Neo4j.
Replacement syntax for deprecated and removed features are also indicated.

[IMPORTANT]
Neo4j 2026.02+ databases explicitly set Cypher 25 as their query language.
Cypher 25 was introduced in Neo4j 2025.06 and can only be used on Neo4j 2025.06+ databases.
Any new Cypher features introduced in Neo4j 2025.06 or later will be exclusively added to Cypher 25.
Features removed in Cypher 25 are still available on Neo4j 2025.06+ databases either by prepending a query with `CYPHER 5` or by having Cypher 5 as the default language for the database.
For more information, see xref:queries/select-version.adoc[].

=== Updates

[cols="2", options="header"]
|===
| Feature
| Details

a|
label:updated[]
[source, cypher, role="noheader"]
----
LOAD CSV WITH HEADERS FROM $csv AS line
CALL (line) {
  MERGE (a:Person {id: line.actorId})
  MERGE (m:Movie  {id: line.movieId})
  CREATE (a)-[:ACTS_IN {name: line.roleName}]->(m)
} IN CONCURRENT TRANSACTIONS OF 500 ROWS
  DISJOINT BY AUTO
----

a| `CALL {...} IN CONCURRENT TRANSACTIONS` now accepts an optional `DISJOINT BY` clause.
This adds optional deadlock prevention scheduling to concurrent transactions.
The runtime schedules batches that share resources serially and batches that do not concurrently, preventing deadlocks rather than recovering from them.
This is particularly useful when importing relationships.

`DISJOINT BY` has three forms:

* `DISJOINT BY (<expr>, ...)`: declares lock-prone resources explicitly per row.
* `DISJOINT BY AUTO`: the runtime infers lock-prone resources automatically.
* `DISJOINT BY NONE`: disables scheduling explicitly, overriding any database-level default.

For more information, see xref:subqueries/subqueries-in-transactions.adoc#disjoint-by[`CALL` subqueries in transactions -> Batch scheduling with `DISJOINT BY`].
